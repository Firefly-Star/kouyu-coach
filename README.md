# 口语训练台

针对**“说话容易结巴、表达容易卡壳”**的本地训练工具。不是一个打分器，而是一份
**有顺序、有验收条件的训练计划**，外加把这一步练到位没有的量出来。

- 全程本地：录音只存在本机 `history/`，不上传。
- 几乎零依赖：Python 3 + numpy。
- 30 秒录音大约 150–300ms 出报告。

```powershell
pip install -r requirements.txt   # 只有一个依赖：numpy
python server.py                  # 打开 http://127.0.0.1:8899
```

> 端口被占用时可以用环境变量改：`$env:KOUYU_PORT = 9000` 后再启动。

## 为什么这样设计

口语表达不是一个能力，是**六个可测量的能力**叠在一起。哪一项弱，听感就卡在哪一处：

| 维度 | 一句话 | 弱的时候听起来是 | 主要练法 |
|---|---|---|---|
| **气息** | 一口气能撑多久 | 一句话没说完就要换气，换气点落在词中间 | 腹式呼吸 + 延长语 + 一口气数数字 |
| **起音** | 开头是撞出来还是送出来 | 每个字像“顶”出来，“呃”“那个”开头 | 轻柔起音（先呼气再出声） |
| **流畅** | 停在哪、停多久 | 句中长停顿，句读处反而不敢停 | 节拍器 + 断句跟读（句内不停） |
| **语速** | 快慢是否可控 | 越说越快然后乱，或一个字一个字地挤 | 三档语速（慢/常/快） |
| **语调** | 有没有起伏和收束 | 像念经；句末悬着，听众抓不到重点 | 重音标记 + 夸张→收敛 + 句末下压 |
| **字音** | 每个字有没有落地 | 吞字、糊过去，别人得靠猜 | 绕口令慢读 + 去填充词 |

**顺序很重要**：气息和起音是物理地基，地基不稳时有再多结构技巧也会更卡。
所以计划是「先地基 → 再节奏 → 再表达 → 最后临场」，而不是六件事一起改。

## 四个阶段（有验收条件，不是练够天数）

| 阶段 | 时间 | 主攻 | 通过条件 |
|---|---|---|---|
| 一 · 打地基 | 第 1 周 | 气息、起音 | 气息 ≥70、起音 ≥78 |
| 二 · 钉节奏 | 第 2 周 | 流畅、语速 | 流畅 ≥63、语速 ≥88 |
| 三 · 上表达 | 第 3 周 | 语调、字音 | 语调 ≥80、字音 ≥82 |
| 四 · 临场 | 第 4 周起 | 即兴、续接 | 流畅 ≥72、语调 ≥86 |

> 这些线是拿 19 条真实录音回归出来的，四关通过率约 84% → 58% → 53% → 16%，
> 呈递减。改动 `analyzer.py` 的计分曲线后，一定要重跑一遍这个分布，
> 否则很容易出现「某一关谁都过不了」或「某一关默认就过」。

**每个阶段独立判定**：前面没过不会挡住后面显示。你可能会看到
「第一阶段未达标、第二阶段已达标」这种组合——这是真实的，不是 bug。

每个阶段有 3~4 个 8~10 分钟的练习动作。每个动作都标了验收方式：

- **可验**（8 个）：报告里能直接读到数字，工具替你验
- **自查**（5 个）：工具测不了（比如「有没有用填充词」「数到 20」），只能你自己对照

> 为什么要有这个区分：以前 13 个动作里有 5 个写着「验收：每 60 秒填充词 ≤ 2」这类
> 条件，但纯信号处理根本听不出「然后」「那个」。用户按计划练完，打开报告，
> **在这些动作上得不到任何反馈**——这比没有验收条件更糟，因为它承诺了做不到的事。

每周节奏（周日只复测，不学新的）：

| 周一 | 周二 | 周三 | 周四 | 周五 | 周六 | 周日 |
|---|---|---|---|---|---|---|
| 气息日 | 起音+节奏 | 断句+绕口令 | 语速+重音 | 语调+去填充词 | 即兴日 | 复测+续接 |

## 今日一题

训练计划页顶部每天换一道开放题（题库 39 题：21 道日题 + 10 道深题 + 8 道工作场景）。

- **同一天反复打开是同一题**：可以练到满意再走，不必担心题变了
- 点「现在讲这道」直接进练习页，带着建议时限（30/45/60/90 秒）
- 练习页的**限时**下拉框选好时间后，录音到点会**自动停止并分析**
- 想换题：点「换一题」，或去左侧「即兴」分组自己挑

> 限时是刻意的压力来源。没有倒计时，人会无限期地「准备一下」——
> 而压力下的卡壳才是真实的卡壳。

| 分组 | 条数 | 练什么 |
|---|---|---|
| 气息 / 起音 / 流畅 / 语速 / 语调 / 字音 | 19 | 六个维度各自的基础段子 |
| **绕口令** | 8 | 按难在哪个音分类：平翘舌、前后鼻音、唇齿、ü 韵、最容易糊的几条 |
| **播音基本功** | 6 | 播音专业的练声常规：口部操、数枣、共鸣、贯口、四声、绕音 |
| **晨读短文** | 8 | 60~200 字递进，说明/叙事/议论/抒情四种文体 |
| 即兴 | 5 | 无稿任务 |

**为什么扩这么多**：原来 21 条朗读素材，练三天就全背下来了，
到那时练的是记忆力，不是口语。现在 41 条 + 39 道即兴题，很难靠背过关。

### 重音标记

素材里用 `‼` 包住重音字，前端会渲染成高亮：

```
‼说清楚‼不是为了显得聪明，恰恰是为了省别人的时间。
```

`text` 字段是去掉标记的干净文本（用于音节计数和展示），`text_raw` 保留原文。
`analyzer.pinyin_syllables` 会显式排除这些标记，否则它们码位 > 0x2E80
会被当成汉字算进期望音节数，导致覆盖率整体偏低。

## 使用循环

1. **训练计划**页看清当前阶段该补哪一项。
2. 点「练这个 →」进练习页，先看**配套练法**（3 步），照做。
3. 按 `🔊 听示范` 听一遍，`🥁 节拍器`（两字一拍）热身。
4. `● 开始录音` → 念/讲 → `■ 停止并分析`。
5. 看报告：**六个维度 + 关键指标 + 节奏图 + 逐句表 + 卡壳点（精确到秒）**。
6. 只重录报告点出的那一句，再整段重录，看分数变化。
7. 「进度」页看六个维度的趋势和全部历史录音。

`先看示例报告` 用内置音频跑一遍完整流程，**不会写入历史**，只是让你先看看报告长什么样。

### 波形就是播放器

报告上方的波形不只是装饰，它承担了全部回听操作：

| 操作 | 效果 |
|---|---|
| 播放中 | 琥珀色竖线实时跟着走，落在哪个字上一清二楚 |
| **单击波形** | 跳到最近的**字**（吸附到音节起点，不是任意时间点），并立即播放 |
| **按住拖动** | 拖动播放头定位；拖出明显距离则框选一段 |
| **框选一段** | 松开后**循环重放**这一段（蓝色选区）——反复磨某一句就用它 |
| `🔁 循环选段` | 没框选时默认取播放头往后 3 秒；再点一次取消 |
| 鼠标悬停 | 显示浅色参考线和时间气泡，按下去之前先知道是第几秒 |

> 前提：服务端必须支持 HTTP Range 请求（已实现 206 Partial Content）。
> 否则浏览器里 `<audio>` 的 `seekable` 是 `[0,0]`，**任何跳转都不会生效**——点了只会从头播。

## 报告怎么读

### 先说语速：两个口径，别混用

语音学里有两个标准指标，含义完全不同：

- **整体语速（speech rate）** = 音节数 ÷ 开口到收尾的总时长，**含停顿**。
  这是人耳实际听到的语速，**也是本工具打分用的口径**。
- **吐字速率（articulation rate）** = 音节数 ÷ 纯发声时长，**扣除停顿**。
  只反映“嘴动得快不快”，作为诊断项给出，不参与语速评分。

为什么要分清：如果拿吐字速率当“语速”，就会出现 **停顿占了 1/3 时间、语速却给满分**
这种自相矛盾的结论。而卡壳恰恰是停顿造成的——把停顿排除在语速之外，
正好掩盖了最该暴露的问题。报告里的**两者之差**就是停顿拖后腿的量化：

> 吐字 4.9 字/秒，整体只有 3.8 字/秒 → 停顿吃掉了 22% 的时间，问题在停，不在嘴。

| 指标 | 含义 | 参考 |
|---|---|---|
| **整体语速 字/秒** | 音节数 ÷ 总时长（**含停顿**），评分依据 | 3.4–4.8；演讲约 4 字/秒 |
| 吐字速率 字/秒 | 音节数 ÷ 纯发声时长（扣停顿） | 通常比整体高 0.5–1.2 |
| 两者之差 | = 停顿造成的损失 | ≥0.8 说明停顿明显拖后腿 |
| 停顿占比 / 说话占比 | 静音时间 ÷ 总时长 | 停顿 <20% 较自然 |
| 最长连续发声 | 一口气能撑多久 | ≥ 2.2 秒说明气息够用 |
| 硬起音比例 | 90ms 内冲到满音量的段占比 | < 15%；越低越柔 |
| 起音爬升 | 振幅 15%→85% 用了多少毫秒 | 硬起音 <18ms；轻柔 30–80ms |
| 长停顿 ≥0.6s | 句内“卡住”的客观证据 | 每分钟 ≤ 2 次 |
| 音节间隔抖动 | 节奏稳定性 | < 0.35 |
| 基频起伏（半音） | 语调抑扬幅度 | 3–8；< 3 偏平 |
| 句末平拖占比 | 句尾是否自然收束 | 越低越好 |

> 注：录不到 6 秒的片段，“每分钟停顿次数”会被放大得很夸张，
> 所以 fluency 计算对短录音做了置信度缩放；判断停顿水平请用 15 秒以上的录音。

**关于“字音”分**：它不是拼音正误识别（那需要云端 ASR）。纯信号处理拿不到音素边界，
正常连读下音节检出率天然在 70–100% 波动，且**每个人、每支麦都不同**。
所以计分时用这段录音自己的基线做归一化，只惩罚**相对**偏差——某句比本段其它句明显更糊才扣分。
绝对值别纠结，**同一个人前后两次比较**才有意义。

## 加自己的材料

编辑 `passages.py`，把 `dim` 设成六个维度之一就会出现在对应分组和阶段推荐里：

```python
FLOW = [
    {"id": "my-1", "dim": "flow", "level": 2, "title": "题目",
     "focus": "这段练什么", "text": "正文……", "tips": "提示……"},
]
```

调整训练计划本身（阶段、验收线、练法步骤）改 `plan.py`。

## 想更严格怎么办（可选）

想判**具体哪个字读错了、声调对不对**，把 `analyzer.py` 上报的音节数换成真正的 ASR 对齐即可：

1. **腾讯云「口语评测」**：直接返回流畅度/准确度/完整度/语速多维分。
   <https://cloud.tencent.com/document/product/1774/107335>
2. **普通话水平测试类 App**（如甘言）：现成、免费、机评口径接近考试，
   但只给考试分，不给停顿时间轴和逐句红黑榜。
3. **DAF（延迟听觉反馈）App**（如 DAF Pro）：口吃/语速专项，把声音延迟回放逼大脑放慢节奏，
   对“越说越快然后卡死”有效。
   <https://play.google.com/store/apps/details?id=co.speechtools.DAFPro>

## 文件说明

```
kouyu_coach/
├─ server.py        本地服务 + 录音存档（历史列表按 mtime 缓存；音频支持 Range 206）
├─ analyzer.py      分析引擎：VAD / 音节 / F0 / 起音 / 六维计分
├─ plan.py          训练计划：六维模型 + 四阶段 + 每周节奏 + 达标判定
├─ passages.py      素材库（按维度分组，无个人化自述）
├─ passages_extra.py 绕口令 / 播音基本功 / 晨读短文
├─ topics.py        即兴题库（39 题：日题 / 深题 / 工作场景）
├─ desktop.py       桌面版入口（打包 exe 用）
├─ build_exe.py     一条命令打包 exe
├─ web/             前端：训练计划 / 开始练习 / 进度
├─ samples/         内置示例音频
├─ history/         每条录音的 wav + 分析 json（这就是你的进度，默认不进版本库）
├─ make_samples.py  合成测试音频（回归用）
└─ test_analyzer.py 回归脚本：python test_analyzer.py
```

## 用合成信号做回归

`samples/` 里的 6 条 wav 不是录音，是用 `make_samples.py` 合成的“可控伪语音”，
分别对应正常 / 长停顿 / 过慢 / 过快 / 语调平 / 漏读一句：

```powershell
python make_samples.py      # 重新生成 samples/*.wav
python test_analyzer.py     # 跑一遍，看六个用例的分数是否落在预期区间
```

改动 `analyzer.py` 的计分逻辑后，先跑这个脚本再提交——它能挡住“语速口径改完
分数全部漂移”这类回归。
